# ML fan shroud — project rules

An end-to-end ML framework on measured excavator cooling-fan data: it predicts cooler air
flows and fan power for untested shroud geometries, with uncertainty, and recommends which
runs to measure next. It also shows industry partners what a complete ML workflow adds
beyond spreadsheet plots. Build plan: the "Fan Shroud ML Framework — Build Proposal" doc;
plain-language methods guide: `guide/fan_ml_methods_guide.html`.

## Layout

| Path | Role |
| --- | --- |
| `settings.py` | Everything dataset-specific: columns, units, derived features, bounds, variants, assumptions |
| `fanml.py` | Analysis helpers; no dataset-specific numbers |
| `fan_ml_framework.ipynb` | The narrative notebook, one dataset at a time (`DATASET = ...`) |
| `run_all.py` | Executes the notebook for every dataset into `outputs/<dataset>/` |
| `tests/` | pytest checks of the data layer and helpers |
| `data/raw/` | The workbook — git-ignored, never edited |
| `outputs/` | Figures, tables, executed notebooks — git-ignored, regenerated by `run_all.py` |

## Rules

- **Never edit the raw workbook.** Corrections are variants in `settings.py`, applied in code and visible in the data-health report.
- **Dataset specifics only in `settings.py`.** If a number describes one sheet, it does not belong in `fanml.py` or the notebook.
- **Every open question is an assumption** in the dataset's `assumptions` list (id, topic, default, status). Answers from the engineers change one entry and the status, then re-run.
- **Physics first.** Prefer physics coordinates (immersion, split, fractions) over raw columns; start with simple models and add complexity only when validation pays for it.
- **Never report a score without saying how it was validated** (leave-one-out, nested, later-runs). Predictions outside the tested range carry a warning.
- **Notebook style.** Markdown explains what and why in plain English; code cells are short and call `fanml`. Each section ends with "Takeaway for engineers" plus a code cell printing dataset-specific findings. Figure titles are descriptive; interpretation goes in the text. Units in every axis label.
- **Data stays private.** Do not commit `data/raw/` or `outputs/`. Commit the notebook with outputs cleared.
- **Portable code.** Python 3.10+, `pathlib` for paths (the main user works on Windows), dependencies only via `requirements.txt`.
